#+title: Seal v0 Odin Implementation Plan

* Purpose

This train implements the accepted =SPEC.org= in Odin so the operator can
compare a complete Odin artifact with the independent Rust train. It changes
implementation language and dependency shape, not Seal behavior.

The Rust integration branch, review branches, pull requests, and generated
files are reference material only. Odin work starts from =origin/main= on
=integration/v0-odin= and must not modify or retarget Rust refs.

* Implementation shape

=SEAL.org= is canonical. It tangles a small executable package under =seal/=,
following the visible structure of =engimatic-systems/8x16=: explicit package
files, Odin core-library imports, named constants, direct procedures, nearby
tests, tabs, =-vet-style=, and =-vet-tabs=. Do not reproduce 8x16 abstractions;
copy its legible source organization.

Expected generated files may include:

- =config_toml/config.odin=: Seal-owned TOML facade with opaque backend state;
- =config_toml/config_test.odin=: facade queries and ownership behavior;
- =seal/main.odin=: arguments, command dispatch, diagnostics;
- =seal/config.odin=: configuration schema, validation, and resolution;
- =seal/config_test.odin=: consequential Seal schema behavior;
- =seal/transfer.odin=: process plan and rsync invocation once pull exists.

Files appear only when current behavior needs them. Car 002 vendors exact
=Up05/toml_parser= commit
=10aee3739d1a144efe79e95d8a094e9c1563bb03= under =vendor/toml/= with its MIT
license and provenance. Vendored upstream source is not generated from
=SEAL.org=. Use the pinned Nix =odin= package for checks.

* TOML and schema boundary

Car 002 owns a small =config_toml= package facade backed at compile time by the
pinned parser. Its public API exposes opaque single-owner document and parse
error handles, =Found=/=Missing=/=Wrong_Type= lookup status, table-key
enumeration, and owned string/string-array queries. Handles must not be copied;
destruction zeros the original. Parser state and errors retain their allocation
allocator, while query results name the allocator callers must use for
destruction. Upstream types do not cross this package boundary. There is no
runtime backend selection, reflection unmarshal, generic schema validator, or
encoder.

=config_toml.parse= knows TOML syntax only. =seal/config.odin= owns explicit
allowed root, peer, tools, and debug keys; required tables and values; unknown
name and type rejection; SSH pairing; absolute tool paths; debug whitelist and
defaults; and local path resolution. Empty SSH strings are invalid, so durable
configuration derives SSH mode from nonempty =peer_ssh= rather than presence
booleans. Car 003 retains its schema-specific writer because the pinned parser
has no encoder.
