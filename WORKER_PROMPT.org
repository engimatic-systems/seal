#+title: Seal v0 Worker Handoff

* Purpose

Implement one assigned Seal v0 ticket in one isolated worktree. Produce the
smallest clear working artifact for that car, record compact evidence, and stop.

Seal transports one opaque mailbox through local or SSH rsync semantics. It
does not interpret, approve, attest, classify, or execute mailbox content.

* Dispatch record

The coordinator fills this block for each cold worker:

#+begin_example
epic: sys-cv8p
ticket: TICKET_ID
car: CAR_NUMBER
worktree: /home/rosin/sys/working/sys-cv8p/CAR-seal-NAME
branch: review/CAR-NAME
target: integration/v0
expected_base: COMMIT
pr: unset
#+end_example

Verify branch, target, and base before editing. Report a mismatch rather than
repairing train topology.

* Authority

Read, in order:

1. =SPEC.org= for normative behavior and non-claims.
2. Assigned tko ticket for current scope and evidence.
3. =PLAN.org= for sequence and review question.
4. =SEAL.org= for canonical implementation once car 001 creates it.

Chat, abandoned branches, generated Rust files, and implementation convenience
do not override those surfaces. Stop on a consequential conflict.

* Minimality rule

Minimality is part of correctness, not a request for compressed or obscure
code. Add a field, abstraction, helper, dependency, validation rule, or test
only when current behavior needs it, a historical exploit boundary requires it,
or live evidence demonstrates the pain.

- Prefer one clear error over an aggregation framework.
- Prefer direct control flow over future-facing types or extension points.
- Prefer clear duplication over an abstraction used once.
- Test the working path and consequential invariants, not parser-library
  behavior or every hypothetical failure.
- Do not add tests merely to increase review confidence numerically.
- Do not implement later verbs, shared frameworks for later cars, aliases, or
  compatibility behavior.

When uncertain, omit the behavior and record the question.

* Train topology

Each branch starts from the operator-approved =integration/v0= tip and targets
=integration/v0=. Cars remain serial; do not prebuild tail branches.

| Car | Ticket | Branch | Goal |
|-
| 001 | sys-ujis | review/001-executable-seed | Literate executable seed |
| 002 | sys-h2e1 | review/002-configuration-cfg | Config and =cfg= |
| 003 | sys-pz3f | review/003-local-init | Local =init= |
| 004 | sys-av6t | review/004-pull | Peer-to-local transfer |
| 005 | sys-rx3t | review/005-push | Local-to-peer reversal |
| 006 | sys-4e48 | review/006-live-ssh-smoke | Tactile SSH round trip |

Do not merge PRs. Do not advance or retarget the train unless the operator asks.

=sys-nvdk= defines a possible later =doctor= command. It is not a v0 car.

* Literate source

- Edit =SEAL.org= before handwritten tangled outputs.
- Put reviewer-facing pseudocode immediately before consequential blocks.
- Split blocks only at stable file or top-level Rust boundaries.
- Keep generated dependency locks outside literate ownership.
- Tangle twice; the second tangle must leave no unexplained diff.

* Hard boundaries

Every car excludes automated execution, approval, attestation, mailbox schemas,
content interpretation, deletion, background behavior, multiple mailboxes,
credential management, remote executable discovery or pinning, and transports
other than local/SSH rsync.

Car boundaries:

- 001: no config, mailbox, SSH, rsync, or later-verb stubs.
- 002: no creation, peer contact, subprocess, or aggregate-error framework.
- 003: no peer contact, remote discovery, transfer, or filesystem transaction
  framework.
- 004: pull only; no push, retry, rollback, delete, or source-link dereference.
- 005: direction reversal only; no separate transport machinery.
- 006: evidence and contract-required defect repair only. Keep
  =agent-dayjob-01= powered off.

Debug config accepts an empty value or one of =-v=, =-vv=, and =-vvv= for each
tool, defaulting to =-v=. Do not implement rsync =--debug=, =--info=, arbitrary
flags, or a general diagnostic-argument parser.

Required checks are clean second tangle, formatter, current tests, and build.
Add only the car-specific interaction or fixture named by its ticket. Keep the
ticket note readable and run =tko lint TICKET_ID=.

Stop after return. Do not review your own work as a separate phase and do not
begin the next ticket.
