#+title: Seal v0.1 experimental mailbox contract
#+date: 2026-07-16
#+options: toc:2 num:nil

* Status

This document teaches an agent how to use the experimental one-shot command
broker on the =seal-v0.1= branch.

This is a workflow convention, not a security proof or stable protocol.  The
operator may replace it as the experiment changes.  A copy placed in a mailbox
is a courtesy copy; the copy committed with Seal is the reference record.

There is no watcher.  The operator manually asks Seal to consider one command.
Publishing a command does not authorize or schedule it.

* Mailbox shape

#+begin_example
mailbox/
  contract.org
  ready/
    <command-id>/
      command.sh
  claimed/
    <command-id>/
      command.sh
      result.toml
      ...files written by the command...
  output/
    <command-id>.out
    <command-id>.err
  world/
    ...persistent working state...
#+end_example

The agent publishes under =ready/=.  The operator claims under =claimed/=.
Captured process output lands under =output/=.  Commands run with =world/= as
their current directory.

* Agent workflow

** Before proposing

Read this contract and inspect the current mailbox:

- =claimed/= and =output/= show earlier disposition and results;
- =world/= contains persistent working state created by earlier commands; and
- a =ready/<command-id>/= entry may remain visible even after claim because
  Seal v0 does not propagate ordinary deletions.

Presence of =claimed/<command-id>/= wins over a duplicate
=ready/<command-id>/=.  Never reuse a command ID.

** Prepare one command

Choose a unique ID containing only ASCII letters, digits, period, underscore,
and hyphen.  Its first character must be alphanumeric.  A UTC timestamp plus a
short description is useful:

#+begin_example
20260716T151500Z-clone-terraform
#+end_example

Create one regular, non-symlink =command.sh=.  Prepare the directory outside
=ready/= when practical, then rename it into =ready/= only after all proposed
files are complete.  The current transport is not a transactional queue; this
staging convention merely reduces partial proposals.

Do not modify a command after publishing it.  A changed request should receive
a new ID.

** Write =command.sh=

=command.sh= is arbitrary Bash interpreted by the operator-side Bash.  It may
perform several sequenced operations and may invoke sibling scripts.  Prefer:

#+begin_src bash
#!/usr/bin/env bash
set -euo pipefail
#+end_src

Make intended effects and important checks visible in comments and output.
Use explicit paths and refuse surprising state when a cheap guard exists.

Seal warns, but does not refuse, when =command.sh= exceeds 40 lines.  Do not
move consequential logic into opaque helpers merely to evade that warning.  If
the command delegates, name the delegated files plainly so the operator knows
what else to inspect.

Do not assume that publication implies approval.  The operator may decline or
edit the script.

** Wait for disposition

The operator manually runs =seal-exec.sh=.  It pulls the mailbox and selects
the most recently modified ready command that has no same-ID claimed entry.
When modification times tie, the lexicographically greatest ID wins.

The operator sees numbered =command.sh= lines, the line count, and a SHA-256
digest.  The operator then chooses:

- =yes=: execute the displayed script;
- =edit=: edit it in =vi=, redisplay it, and decide again; or
- anything else: refuse it.

Editing changes the executed proposal.  Inspect =edited= and the claimed
=command.sh= when interpreting the result.

** Read the result

Seal returns:

- =output/<command-id>.out=: captured standard output;
- =output/<command-id>.err=: captured standard error; and
- =claimed/<command-id>/result.toml=: disposition and attempt metadata.

Normal completion resembles:

#+begin_src toml
status = "completed"
command_id = "20260716T151500Z-clone-terraform"
command_sha256 = "..."
edited = false
started_at = "2026-07-16T15:16:00Z"
finished_at = "2026-07-16T15:16:03Z"
exit_code = 0
#+end_src

Known status values in the spike are:

- =refused=: operator did not authorize execution;
- =invalid=: claimed directory lacked a regular, non-symlink =command.sh=;
- =started=: execution began but the local result has not reached completion;
- =completed=: the process exited; inspect =exit_code= for success or failure.

An absent or incomplete remote result does not prove that execution never
began.  Transport happens after execution.  Ask the operator rather than
automatically resubmitting an effectful command whose outcome is uncertain.

Files written elsewhere in the mailbox are ad-hoc workspace or result
material.  Seal attributes only the captured streams and =result.toml=
mechanically.

* Execution world

The proposed script runs with:

- current directory =mailbox/world/=;
- the operator's inherited environment, including any active =mise= context;
- =TMPDIR= set to =mailbox/world/.tmp=;
- the host filesystem mounted read-only;
- the whole mailbox mounted writable;
- the approved =command.sh= snapshot mounted read-only over its claimed path;
  and
- ordinary network access unchanged.

The writable =world/= is intended to carry state between commands: cloned
repositories, Terraform working directories, saved plans, and similar
material.  A later proposal may depend on state created by an earlier command.

The whole mailbox is technically writable so commands may leave ad-hoc files
beside their claimed request.  By convention, do not rewrite queue lifecycle,
other commands, captured outputs, or =contract.org= unless that mutation is the
explicit reviewed purpose.

Read-only host mounts do not make a command harmless.  A command may read host
material exposed in the namespace, use inherited credentials, access the
network, and mutate external systems such as Azure.  The operator's review is
the safety decision in this experiment.

Avoid printing credentials or copying secrets into mailbox files.  Everything
under the mailbox may return to the agent side.

* Example: establish repository state

The agent might publish:

#+begin_src bash
#!/usr/bin/env bash
set -euo pipefail

if [[ ! -d terraform/.git ]]; then
  git clone https://example.invalid/terraform.git terraform
fi

git -C terraform fetch origin
git -C terraform status --short --branch
#+end_src

A later command can run inside that persistent checkout by using explicit
paths, for example =tofu -chdir=terraform plan=.  Repository state remains an
implicit part of the operator-understood world; Seal does not attest Git
semantics in this spike.

* Purge behavior

The operator may explicitly run =seal-exec.sh purge=.  After a literal =purge=
confirmation, it removes local =ready/= and uses a deleting rsync scoped to
peer =ready/= only.

Purge intentionally destroys every unclaimed command visible in that subtree.
There is no agent/operator lock protocol yet.  If a ready command disappears
without a claimed result, coordinate with the operator before submitting a new
unique request.

* Non-claims

This spike does not provide:

- automatic polling, scheduling, or notification;
- command-language validation or a claim that reviewed code is safe;
- isolation from network or external credentialed effects;
- transactional shared-directory queue semantics;
- reliable deletion propagation during ordinary claim;
- immutable or exhaustively represented world state;
- automatic retry after an uncertain execution; or
- a stable protocol promised to future Seal versions.
